`gerdoo-dyland` — a menu-bar utility that turns the MacBook notch into an interactive control centre.

**Requires macOS 14 or later.** This build is universal: it runs natively on both Apple silicon and Intel Macs.

## What's new since 0.2.0

**Intel Macs work again (#3)**

The DMG is now a universal binary carrying both `x86_64` and `arm64` slices, so one download runs natively on any Mac that can run macOS 14. Since 0.1.1 the releases have been Apple-silicon-only — if you have an Intel Mac, nothing published in the last two versions would launch for you at all. That is fixed.

The release workflow now asserts both slices are present inside the mounted DMG before it publishes anything. The CI runner is Apple silicon and the Intel half is cross-compiled, so "it built" is not the same as "both architectures are actually in there"; a half-universal build that stranded Intel users again would now fail the release rather than ship.

**Install instructions that work on current macOS (#2)**

The previous notes told you to right-click the app and choose **Open**. Apple removed that bypass in macOS 15, so on any current system that advice leads to a dialog with a single **Done** button and no way through. The instructions below are the two routes that actually work, and they now start with the step that was missing entirely: drag the app out of the disk image first, because launching it from the read-only DMG fails with an identical-looking dialog for a completely different reason.

**Honest note:** the app's behaviour is unchanged from 0.2.0. Nothing in the notch, the shelf, Now Playing, the clipboard, or Quick Actions works differently. If you are on Apple silicon and already running 0.2.0, the only thing this gives you is a larger download.

## Downloads

## Before you open it

The app is **ad-hoc signed and not notarized**, so the first launch is blocked with *"Apple could not verify this app is free of malware."*

**First, drag the app out of the DMG into Applications.** Launching it while it is still on the mounted disk image fails for a second, unrelated reason, and the dialog looks identical.

Then pick either route:

- **Terminal** — clear the quarantine flag and open it normally:

  ```
  xattr -dr com.apple.quarantine /Applications/gerdoo-dyland.app
  ```

- **No Terminal** — double-click the app, dismiss the warning, then go to **System Settings ▸ Privacy & Security**, scroll to the Security section, and click **Open Anyway** next to the message about gerdoo-dyland.

On **macOS 15 and later, right-clicking the app and choosing Open no longer works** — Apple removed that bypass.

Proper Developer ID signing and notarization would remove this step entirely. It needs an Apple Developer account and is not set up yet.

## Permissions

Only two, both optional:

- **Automation** (Music / Spotify) — asked for the first time you press play/pause/next. Without it, track metadata still appears; only the transport buttons and the progress bar stop working.
- **Login item** — only if you turn on "Launch at login".

Not requested: Accessibility, Screen Recording, Full Disk Access, Camera, Microphone, or Contacts.

## Known limitations

- **The Intel slice has never been run.** It compiles and both architectures are verified present, but no Intel Mac was available to launch it on. If it misbehaves there, that is unexplored territory.
- **No system-wide Now Playing.** macOS exposes no public API for it — `MediaRemote` is private and, since macOS 15.4, entitlement-gated. This app integrates per player and ships Music and Spotify; anything else playing audio (a browser tab, VLC, a game) is invisible to it.
- **Drags register only once they reach the notch's catch zone.** No public API reports a drag session happening elsewhere on screen.
- **The waveform is procedural.** Reading another app's audio levels requires a system audio tap and its permission.
- **The notch stays visible over full-screen apps.**
- **The shelf is in-memory** — files stay until removed, cleared, or the app quits.
- Not sandboxed, so it cannot ship on the Mac App Store as configured.

Full detail, including the reasoning behind each constraint, is in the [README](https://github.com/ranjbar-amirabbas/gerdoo-dyland#readme).
